# Портфолио Александры Итуниной

Полностью статический сайт для GitHub Pages и открытия `index.html` напрямую. Веб-сервер не нужен. Python используется только во время сборки данных и PDF.

## Локально

1. После изменения папок `portfolio` запустите `Собрать портфолио.command`.
2. Откройте `index.html` двойным щелчком. После правок обновите страницу.

Для другой машины с Python 3.12:

```sh
python3 -m venv .venv
.venv/bin/pip install -r requirements-build.txt
.venv/bin/python scripts/build.py
```

## Структура

- `index.html` — разметка и тексты.
- `assets/styles.css`, `assets/app.js`, `assets/portrait-pistachio.png` — оформление, поведение и фото.
- `portfolio/01 Название/01.webp` — изображения, префикс задаёт порядок вкладок и скрывается на сайте.
- `portfolio/99 Отдельные слайды` — последняя вкладка.
- `scripts/build.py` — создаёт `portfolio.json`, `assets/portfolio-data.js`, `downloads/portfolio.pdf`.
- `.github/workflows/pages.yml` — сборка и публикация при push в `main` или ручном запуске Actions.
- `local-only/` — личные исходники и архив старых скриптов, исключён из Git.
- `dist/` — только готовые публичные файлы; создаётся командой `python scripts/build.py --output dist`.

Генерируемые JSON, JS-данные и PDF не коммитятся: их пересоздаёт сборка. JSON используется по HTTP(S), а небольшой JS-файл с теми же путями позволяет работать через `file://`, где fetch локального JSON блокируется браузером. Изображения не встраиваются в HTML или JS. PDF — обычная относительная ссылка.

## GitHub Pages

1. Закоммитьте и отправьте изменения в `main`.
2. В репозитории откройте Settings → Pages → Build and deployment → Source и выберите **GitHub Actions** (вместо Deploy from a branch).
3. Сохраните Custom domain: `aitunina-design.ru`; DNS менять не нужно, если домен уже работает.
4. Откройте Actions → Build and deploy portfolio. Workflow собирает данные/PDF и публикует только `dist`.

После этого достаточно отправлять изменения папок портфолио в `main`. Сборка выполняется до каждой публикации. Запуск workflow вручную доступен через Run workflow.

Перед публикацией Actions также проверяет сборку, качество исходника фото, вёрстку и галерею в Chromium и WebKit. Если проверка не пройдена, новая версия не публикуется; измерения и скриншоты доступны в артефакте `layout-qa` этого запуска. Локальный запуск и границы проверок описаны в [tests/README.md](tests/README.md).

## Обновления и кеш браузера

GitHub Pages отдаёт HTML и ресурсы с `Cache-Control: max-age=600` (проверено на домене 13 сентября 2026 года). Поэтому до обновления HTML браузер или CDN может показывать прежнюю версию в течение 10 минут. Завершение push ещё не означает завершение публикации: сначала дождитесь зелёного запуска Actions.

При сборке `dist` CSS, JS, шрифты, фото и логотипы получают относительные ссылки с версией по содержимому файла. Версии слайдов и PDF входят и в локальные данные портфолио. Замена файла под прежним именем меняет его URL автоматически, поэтому после получения нового HTML браузер запрашивает актуальные ресурсы. Исходный `index.html` остаётся удобным для ручного редактирования и открытия через `file://`.

Это не отменяет кеш самого HTML на стороне Pages. Для немедленной проверки после успешного деплоя можно один раз открыть `https://aitunina-design.ru/?v=<хэш нового коммита>`. Постоянно очищать историю Safari не требуется. Принцип версионирования описан в [MDN: HTTP caching](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/Caching#cache_busting).

PPTX, локальные настройки редактора, `.DS_Store`, Python-кеши и прежние серверные скрипты больше не отслеживаются. Их удаление из следующего коммита не удаляет старые копии из истории Git.
